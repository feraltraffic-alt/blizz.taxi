# Уязвимости: проверки и сроки (REQ-SEC-12)

## Что проверяется

На каждый push CI запускает `scripts/security-scan.sh` (Trivy):

- **Зависимости:** уязвимые зависимости Maven (`server/pom.xml`) и npm (`packages/contracts`).
- **Секреты:** ключи, токены и пароли, случайно попавшие в репозиторий.
- **Конфигурация:** ошибки в `server/Dockerfile` и compose-файлах `deploy/`.
- **Образ сервера:** собранный образ (ОС-пакеты и JAR).

Сборка падает на HIGH и CRITICAL, у которых есть исправление. Найденное видно в аннотациях CI, по одной строке на находку. Dependabot (`.github/dependabot.yml`) каждую неделю открывает обновления для Maven, npm и GitHub Actions.

## Сроки устранения

| Уровень  | Срок     | Что делаем |
|----------|----------|------------|
| CRITICAL | 7 дней   | Обновляем или убираем зависимость. Если уязвимость эксплуатируется в нашей конфигурации, исправление выпускаем вне очереди. |
| HIGH     | 30 дней  | Обновляем в ближайшем релизе. |
| MEDIUM   | 90 дней  | Обновляем вместе с плановыми обновлениями. |
| LOW      | по плану | — |

Срок считается с момента, когда находка появилась в CI или пришла от Dependabot.

## Исключения

Исключения пишутся в `.trivyignore`, по одному ID на строку. Над каждым ID — комментарий, который отвечает на три вопроса:

- почему уязвимость к нам не относится или почему её исправление ждёт;
- кто так решил;
- до какой даты пересмотреть (`exp:YYYY-MM-DD`; после этой даты Trivy снова считает находку ошибкой).

Исключение без причины и без даты на ревью не принимается.

Пример:
```
# Уязвимость в функции X библиотеки Y; мы её не вызываем (проверено поиском по коду). Решил ведущий, 28.10.2026.
CVE-2026-00000 exp:2026-12-31
```
