# Восстановление из резервной копии

Когда нужно: база потеряна или испорчена, и площадку поднимают из копии. Проверка этого пути выполняется при каждом полном прогоне песочницы (шаг «Back up, restore…» в `.github/workflows/sandbox.yml`, `scripts/sandbox/backup-restore.sh`).

## Что нужно заранее

- **Копии базы:** `deploy/backup.sh <файл>` по расписанию. Подключение задают переменные `PGHOST`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`, а `pg_dump` должен быть версии 18. Скрипт проверяет, что файл читается.
- **Журнал удалений** (`ERASURE_JOURNAL_DIR`, ADR 0013) лежит на отдельном надёжном хранилище и **не** входит в копию базы. Резервируйте его отдельно, только дописыванием. Без него клиенты, удалённые после копии, вернутся с телефонами.
- **Мастер-ключ** (`SECRETS_MASTER_KEY`): без него ключи интеграций из копии не расшифровать. Он хранится в хранилище секретов, не рядом с копией.

## Сделать

1. **Остановите все экземпляры сервера:** два сервера на разных базах — худшее, что может случиться.
2. **Создайте пустую базу с PostGIS** (`create database blizz_restored template template_postgis`, или `create extension postgis` в новой базе).
3. **Восстановите:** `deploy/restore.sh <файл> blizz_restored`.
   - Скрипт откажется работать, если в базе уже есть таблицы приложения.
   - В конце он печатает, сколько миграций было применено к копии.
4. **Запустите один экземпляр сервера** на восстановленной базе (`DB_URL`) с **тем же** `ERASURE_JOURNAL_DIR` и тем же `SECRETS_MASTER_KEY`.
   - При старте сервер повторно анонимизирует каждого клиента из журнала, который в копии ещё с данными.
   - Flyway применит миграции новее копии.
5. **Проверьте:**
   - `/readyz` отвечает;
   - в логе есть строка `Re-applied N anonymizations from the erasure journal`, если удаления были после копии;
   - проверки согласованности ([invariants.md](invariants.md)) зелёные.
6. **Запустите остальные экземпляры.**
   - Платежи, которые банк провёл после момента копии, найдёт ежедневная сверка ([payment-reconciliation.md](payment-reconciliation.md)).
   - Операции, которых в копии нет, требуют ручного решения с причиной.

## Что потеряно

Всё, что случилось после копии: заказы, сообщения, изменения настроек. Удаления клиентов не теряются благодаря журналу (T-39). Сообщите владельцу время копии и время сбоя.
