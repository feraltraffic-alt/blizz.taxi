## Server work left

All of sections 16-17 and 20-22 belong to slices S-01, S-05, S-06, S-08, S-09 of section 29, i.e. M1, except 22.3 (M2). So every item below is **needed before launch (M1)** unless it says otherwise.

### Payments and debt
- **REQ-PAY-02 (M1):** put an order-level deadline on AWAITING_PAYMENT. When it passes with the hold still UNKNOWN or PENDING, end the order UNFULFILLED, mark the hold for release (void on a late success) and tell the rider.
- **REQ-PAY-18, REQ-API-11, AC-21 (M1):** add a rider obligation view and repayment: `GET /payments/{id}`, `POST /obligations/{id}/payment-sessions`, and an obligation record (original amount, repayments, remainder). Blocking new orders while a debt is open waits for Q-10.
- **REQ-DATA-01 (M1, small):** `WayForPayProvider.amount()` must use the currency's fraction digits, not a fixed scale of 2.

### Ledger and reports
- **REQ-LED-05 (M1):** add a "pending accounting" indication (a completed trip whose `TripCompleted` is not posted yet), shown to staff and on driver earnings, plus a specific alert when that posting is late.
- **REQ-LED-09 (M1):** return and store the UTC bounds and the timezone with finance/order reports and `report_export`.

### Notifications
- **REQ-NTF-03, AC-19 (M1):** take a notification's deadline from the event itself (the offer's `expires_at`). Before sending, re-check that the offer or assignment is still current, and drop superseded "driver assigned" pushes and SMS. Add a test for reassignment.

### API conventions
- **REQ-API-02 (M1, post-launch per the previous audit):** move provider callbacks to `/webhooks/{provider}/{merchantRef}`, keeping the old path during the switch.
- **REQ-API-07 (M1):** fill `current_version` on VERSION_CONFLICT and STATE_CONFLICT, as `common.yaml` already promises.
- **REQ-API-08 (M1):** add `retryable` and `retry_after_seconds` to PROVIDER_UNAVAILABLE and other temporary 5xx/503 problems.
- **REQ-API-09 (M1, post-launch per the previous audit):** use a stable created_at+id cursor on every list, with default 50 and max 100, and no offset paging.
- **REQ-API-11 (M1):** either use `AcceptedOperation` (202 plus `status_url`) for a card order waiting for its hold, or correct the 201 description and add a status endpoint.
- **AC-21 (M1):** add a contract test over the M1 registry rows (scope, idempotency, error schema), including admin and operator paths. Add an HTTP test showing that a repeated POST /orders after a timeout returns the original order_id. Missing non-owner registry endpoints: admin `GET /orders` and `/orders/{id}/timeline`, operator `manual-offers` (post-launch per the previous audit), and the rider payment endpoints above.

### Data and migrations
- **AC-20 (M1):** add an upgrade test that migrates a database populated at the previous release's schema and checks the trips survive.
