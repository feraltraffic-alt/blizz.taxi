# 0007. Кто отменил заказ и по какой причине

- Статус: принято владельцем продукта (B), 27 октября 2026
- Основание: REQ-CAN-*, REQ-ADM-02 (история заказа)

## Решение

1. **В заказе фиксируется, кто отменил:** пассажир (`RIDER`), сотрудник — оператор или администратор (`STAFF`) — или водитель (`DRIVER`). Приложения и панели показывают «Заказ отменён пассажиром / оператором / водителем». Статус остаётся один — `CANCELLED`; кто отменил, хранится в поле `cancellation.by`.
2. **Причины отмены — справочник в настройках**, отдельный список для каждой стороны: причины пассажира, водителя и сотрудников. У причины есть:
   - код, который не меняется;
   - название на языках службы (обязательно на языке по умолчанию, по умолчанию русский);
   - порядок показа;
   - признак «активна».

   Причины не удаляются, а выключаются, чтобы история не теряла смысл. Меняет справочник право `settings.manage`, каждое изменение пишется в аудит.
3. **У причины водителя есть флажок, что происходит с заказом:**
   - «вернуть в эфир»: водитель отказался, заказ ищет другого водителя (например, «Неисправность автомобиля»);
   - «отменить заказ»: заказ отменён водителем (например, «Пассажир попросил отменить»).
4. Причина водителя `NO_SHOW` («Пассажир не вышел») всегда проходит проверку минимального ожидания после прибытия, даже если её выключили в списке.
5. **В заказе сохраняется код причины и её названия на момент отмены.** Поэтому последующее переименование причины не меняет прошлые заказы.
6. **История заказа для панели** (`GET /api/operator/v1/orders/{order_id}/events`) — каждое событие с типом, временем, кем сделано (имя и роль сотрудника, имя водителя) и причиной. Из неё панель строит строки вида «Оператор Анна Ковальчук отменила заказ по причине «Пассажир попросил»». Имя и роль сотрудника показываются текущие.
7. Плата за отмену по причине — вопрос Q-07, здесь не решается.
