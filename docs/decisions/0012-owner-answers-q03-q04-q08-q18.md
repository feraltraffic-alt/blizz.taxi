# 0012. Ответы владельца: Q-03, Q-04, Q-08, Q-18

- Статус: принято владельцем продукта (B), 27 октября 2026.
- Закрывает: Q-03 (несколько заказов), Q-04 (чаевые; оценки — уже решены 27.10, см. ниже), Q-08 (геокодер), Q-18 (SIP, SMS, голосовой код).
- Уточнения владельца по чаевым, лимиту заказов и записи звонков — 27.10.2026, внесены ниже.

## Q-03. Несколько активных заказов

1. Пассажир может держать **несколько активных заказов одновременно, не больше 3** на аккаунт плательщика (настройка `active_orders_per_payer`, по умолчанию 3).
2. В заказе можно указать **номер телефона того, кому заказывают** такси (получатель поездки, REQ-OPS-02): водитель видит и звонит ему; плательщик — владелец аккаунта.
3. «Активный» — любой заказ не в конечном состоянии; **предзаказы тоже считаются** в лимит (подтверждено).

## Q-04. Чаевые (и оценки)

1. Чаевые включены и **необязательны**: экран чаевых только предлагается, пассажир может его пропустить, по умолчанию ничего не выбрано и ничего не списывается. Если пассажир решил оставить чаевые, он выбирает **10 %, 15 %, 20 % или 25 %** от стоимости поездки — каждая сумма **округляется вверх до целой единицы валюты** — или вводит свою сумму.
2. Своя сумма: **минимум 1 единица валюты, максимум — стоимость поездки, округлённая вверх** до целой единицы.
3. Оценки (решено ранее 27.10): обе стороны оценивают друг друга 1–5; правка 24 часа (настройка); комментарии видят только сотрудники; водитель видит только среднее (сотые).
4. **Способ оплаты чаевых — по способу оплаты заказа** (подтверждено): заказ картой — чаевые отдельным списанием с той же сохранённой карты; наличными или терминалом водителя — пассажир передаёт чаевые водителю сам, приложение их только фиксирует; заказ, целиком оплаченный бонусами, — чаевые с бонусного счёта, если хватает, иначе основным способом заказа.
5. **Чаевые целиком получает водитель, комиссии службы нет** (подтверждено); в журнале — сразу на баланс водителя (`DRIVER_PAYABLE`): картой — Дт `PROVIDER_CLEARING`, бонусами — Дт `RIDER_WALLET`; наличные и терминал через службу не проходят.
6. **Оставить чаевые можно 24 часа после поездки** — тот же срок, что у правки оценки (подтверждено), отдельная настройка.

## Q-08. Геокодер и карта

1. Геокодер выбирается в админке: **встроенный**, **Google**, **Visicom**.
2. **Встроенный** — собственный справочник адресов службы, который сотрудники редактируют в админке (уже есть: «свои адреса», задача #17); карта в приложениях и админке — **Leaflet** с подложкой OpenStreetMap (правила использования тайлов OSM соблюдаются; для нагрузки — свой или платный сервер тайлов).
3. **Результаты внешних геокодеров (Google, Visicom) в базу не сохраняются** — так требуют лицензии. Ключи — в админке, зашифрованы (как остальные интеграции).
4. Повторные адреса берутся из **истории заказов клиента**: адрес, который клиент уже заказывал, есть в его заказе и предлагается из истории без нового запроса к геокодеру; со временем запросов к внешнему геокодеру становится меньше.
5. Как устроено (задача #58): модуль `geocoding` выбирает провайдера по «Интеграциям» (`geocoding.provider`, ключи Google и Visicom — секреты); поле адреса в приложениях и у оператора — `GET /api/{rider|operator}/v1/places`: сначала места из истории заказов клиента (для оператора — клиента по номеру звонящего), затем свои адреса, затем результаты провайдера; ответы провайдера не сохраняются. Неработающий провайдер, отсутствующий ключ или исчерпанный лимит вызовов оставляют только историю и свои адреса. Карта Leaflet + OSM — значение `OSM` в `maps.provider`, без ключа.
6. **Внимание по Google:** условия Google Maps Platform ограничивают показ результатов Geocoding API — как правило, вместе с картой Google и с атрибуцией. С картой Leaflet + OSM это нужно проверить юридически до включения Google; Visicom и встроенный справочник этого ограничения не имеют.
7. Маршруты и время в пути — GraphHopper (облачный API, ключ в админке; собственный сервер — задача #43).

## Q-18. Телефония и SMS

1. **SIP** — собственный сервер на базе **Asterisk** в контейнере.
2. **SMS-провайдер** для начала — **TurboSMS**; дальше будут подключаться другие.
3. **Голосовой код**: при входе можно позвонить клиенту и произнести код подтверждения голосом (через Asterisk).
4. **Способ доставки кода выбирается в админке**: голосовой звонок, TurboSMS, … (список растёт с провайдерами). Ключи — в админке, зашифрованы.
5. **Запись звонков делается обязательно и хранится** (подтверждено): отдельное хранилище с ограниченным доступом по праву, без публичных ссылок, каждое прослушивание — в аудит (REQ-OPS-09). Срок хранения — Q-19 (не задан; до решения не удаляется автоматически).
6. Подменные номера — остаются открытыми.

## Что меняется в спецификации

- REQ-RID-03: лимит 1 → до 3 активных заказов, получатель с телефоном.
- REQ-RID-08 / `tips.enabled`: чаевые включены по правилам выше.
- REQ-GEO-11: постоянного кэша внешних геокодеров нет.
- Реестр конфигурации: `active_orders_per_payer = 3`, `tips.presets = 10/15/20/25 %`, `tips.window = 24h`, `geocoder.provider`, `otp.channel`, `calls.recording = on`.
