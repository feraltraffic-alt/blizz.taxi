# 0008. Оплата картой (S-09)

- Статус: принято владельцем продукта (B), 27 октября 2026 — закрывает Q-09 для M1
- Основание: раздел 16, REQ-PAY-01…14, REQ-PAY-18…20, T-23…T-27; страница WayForPay «Для такси-сервисов»

## Решения владельца (Q-09)

1. **Карта привязывается в приложении** один раз (с 3-D Secure). Дальше заказы оплачиваются без ввода данных — по токену карты провайдера (`recToken` у WayForPay). Токен привязан к провайдеру, мерчанту и пассажиру и не переносится между мерчантами (REQ-PAY-08). PAN/CVV платформа не видит.
2. **Холд до поиска водителя.** Заказ с картой создаётся в `AWAITING_PAYMENT`; поиск начинается только после подтверждённого холда (REQ-PAY-01). Отказ — заказ не выполняется; неизвестный результат — сверка, поиск не начинается (REQ-PAY-02, T-23).
3. **Холд = ровно согласованная цена**, без запаса (REQ-PAY-03).
4. **Итог выше холда** (платное ожидание): холд списывается полностью, разница досписывается отдельным списанием с сохранённой карты; не прошло — долг пассажира (REQ-PAY-05, REQ-PAY-18). Итог ниже — списывается итог, остаток холда освобождается.

## Провайдер

- Первый адаптер — **WayForPay**, мерчант задаётся на город (у разных служб и городов свои мерчанты). Секреты — только из окружения.
- Операции: привязка карты — Card Verify (`/verify`, сумма 0, `paymentSystem=lookupCard`) → `recToken`; холд — `CHARGE` с `merchantTransactionType=AUTH` и `recToken`; списание — `SETTLE`; доплата — `CHARGE` `SALE` по `recToken`; снятие холда и возврат — `REFUND` (статус `Voided`/`Refunded`); сверка — `CHECK_STATUS`. Подпись HMAC_MD5 секретом мерчанта по полям, перечисленным в документации, через `;`.
- Каждая внешняя операция — отдельная запись `payment_operation` со своей стабильной ссылкой (`orderReference`); при таймауте статус `UNKNOWN` и сверка через `CHECK_STATUS`, без нового списания (REQ-PAY-10). Входящие уведомления (`serviceUrl`) проверяются по подписи, мерчанту, сумме и валюте, складываются во входящий журнал и дедуплицируются; старое уведомление не откатывает итоговый статус (REQ-PAY-11…13).
- Для тестов и песочницы — поддельный провайдер `FAKE` с тем же контрактом.

## Порядок работ

- A — модуль платежей, привязка карты, адаптер WayForPay, приём уведомлений.
- B — холд до поиска, отмена холда при отмене заказа, поздний успех после отмены (T-23).
- C — списание после поездки, доплата, долг пассажира, проводки в журнале.
