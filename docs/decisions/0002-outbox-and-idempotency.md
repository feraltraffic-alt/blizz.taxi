# 0002. Собственный outbox и идемпотентность команд

- Статус: принято для S-01 (D)
- Дата: 26 октября 2026
- Основание: REQ-ENG-05, REQ-ENG-06, REQ-API-04…06, раздел 21.2

## Решение

**Outbox.** Собственные таблицы `outbox` и `consumer_inbox` вместо реестра публикаций Spring Modulith. ТЗ допускает оба варианта; свой даёт:
- конверт событий, совпадающий с контрактом (`event_id`, `aggregate_version`, `correlation_id`…);
- аренду пачки (`lease_owner`, `lease_until`) и `FOR UPDATE SKIP LOCKED` для нескольких реплик;
- явные `attempts`, `next_attempt_at`, экспоненциальную задержку и состояние `FAILED`;
- схему только через миграции Flyway.

Доставка «хотя бы один раз»; каждый обработчик выполняется в своей транзакции вместе с записью в `consumer_inbox`, поэтому повторная доставка его не повторяет. Внешние эффекты (банк, SMS) обязаны быть идемпотентными сами (REQ-ENG-06).

Spring Modulith остаётся для проверки границ модулей.

**Идемпотентность.** Квитанция `command_receipt` вставляется до выполнения команды и в той же транзакции. Конкурентный дубль ждёт на первичном ключе и читает сохранённый результат; при ошибке квитанция откатывается вместе с командой. Ключ — субъект + операция + `command_id`. Квитанции хранятся весь срок жизни объектов, TTL нет.

**Аудит.** `audit_log` только на добавление: UPDATE, DELETE и TRUNCATE отклоняет триггер БД.

## Последствия

- Каждый новый обработчик событий получает стабильный `consumerId`; смена идентификатора означает повторную доставку прошлых событий.
- Мониторинг: возраст старейшего `PENDING` и число `FAILED` (REQ-OBS-03) — добавить вместе с метриками.
- Очистка доставленных событий `DONE` — отдельное задание после утверждения сроков хранения (Q-19).
