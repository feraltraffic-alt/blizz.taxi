# 0014. Ответ владельца: Q-10, долг пассажира

- Статус: принято владельцем продукта, 1 ноября 2026.
- Закрывает: Q-10 в части пассажира (REQ-PAY-18, `passenger_debt.block_new_orders`). Долг водителя решён раньше: лимит в админке по валюте, выше лимита — нет новых заказов (REQ-PAY-16).

## Решение

1. **Пассажиру с долгом новые заказы запрещены.**
2. **Порог задаётся в админке**, по валюте: настройка сервиса `rider_debts.allowed_minor`. Пока долг не больше порога, пассажир заказывает; выше порога — нет. Для валюты без порога он равен 0: запрещает любой долг.
3. **Отсрочки нет**: запрет действует сразу, как только долг подтверждён.

## Как устроено

- Долг — это остаток пассажира на `RIDER_RECEIVABLE` по заказам, оплата которых закончилась (`PAID`, `PARTIALLY_PAID`, `CASH_REPORTED`, `TERMINAL_REPORTED`). Это те же обязательства, что пассажир видит и оплачивает в приложении (#140). Оплата, которая ещё идёт, и ответ банка `UNKNOWN` — не долг.
- Остатки складываются по валюте. Если хоть в одной валюте сумма больше порога этой валюты, новый заказ (сейчас или на потом) отклоняется: **403 `RIDER_HAS_DEBT`**. Заказ не создаётся, котировка не тратится.
- То же для заказа по телефону, когда номер звонящего принадлежит пассажиру с долгом: оператор видит причину и может сказать её звонящему.
- Это финансовое ограничение, а не блокировка аккаунта (REQ-USR-17): состояние аккаунта не меняется. Пассажир по-прежнему входит, видит свой долг и оплачивает его картой. После оплаты запрет снимается сам.
- Уже созданные заказы не трогаются.
- Спорные суммы: долгом считается то же, что журнал оставляет пассажиру и что он видит в списке своих обязательств; решение спора по наличным меняет журнал, а с ним и запрет.
