# 0015. Ответ владельца: Q-19, сроки хранения

- Статус: принято владельцем продукта, 1 ноября 2026.
- Закрывает: Q-19 в части сроков хранения. Остаются открытыми: legal hold (запрет удаления на время спора или суда) и трансграничная передача данных.

## Решение

1. **Сроки хранения задаются в админке**: раздел «Хранение данных», настройка `retention`, по виду данных, в днях.
2. **0 — хранить бесконечно.** Для данных службы это значение по умолчанию.
3. **Служебные записи сервера сохраняют свои сроки по умолчанию.** Это рабочий мусор, а не данные службы. Без чистки эти таблицы растут без конца и замедляют сервер (#194), а коды из SMS содержат номера телефонов. Администратор может поставить любой из этих сроков в 0.

| Вид (`retention`) | Что | По умолчанию, дней |
|---|---|---|
| `sessions` | сессии входа и токены обновления | 30 |
| `sign_in_codes` | одноразовые коды входа | 90 |
| `code_deliveries` | записи об отправке кодов | 90 |
| `delivered_events` | доставленные события outbox (`DONE`) | 30 |
| `consumer_receipts` | отметки обработанных событий | 30 |
| `command_receipts` | квитанции повторов команд | 30 |
| `upload_sessions` | незавершённые загрузки файлов | 7 |
| `quarantined_files` | файлы, отклонённые проверкой | 30 |
| `call_recordings` | записи звонков (наши файлы и копии на Asterisk, включая отклонённые проверкой) | **0** |

## Как устроено

- Это сделано в #118: `configuration/RetentionSettings`, `platform/internal/RetentionRunner`.
  - Изменение доступно сотруднику с `retention.manage` во всех городах.
  - Каждое изменение — новая версия с автором и причиной.
- **Данные службы автоматически не удаляются:** заказы, поездки, журнал денег, чаты, обращения, аудит.
  - Исключение — данные пассажира, который сам запросил удаление аккаунта (#144). Его записи звонков удаляются при любом сроке.
- **Записи звонков, которые сервер отклонил при проверке файла**, остаются на Asterisk, пока у `call_recordings` срок 0. Если срок задан, задача хранения удаляет и их вместе с остальными записями старше срока (`CallRecordingRetention`). Этим закрыт последний пункт аудита 29.10 (#112).
